Algoritmia desde cero

Primero entendemos el problema y el diagrama. Después lo llevamos a Scratch.

PASO 01/10 0–5 min

¿Qué es un algoritmo?

Un algoritmo es una serie de pasos ordenados para resolver un problema. No hace falta programar todavía.

1 · Entender

¿Qué problema tengo que resolver?

2 · Ordenar

¿Qué pasos debo hacer y en qué orden?

3 · Comprobar

¿Funciona con distintos datos?

Ejemplo cotidiano: piensa los pasos para preparar un vaso de leche con cacao. ¿Qué pasaría si cambias el orden?
Idea clave: primero pensamos el algoritmo. El diagrama y Scratch son dos formas distintas de representar esa misma solución.

PASO 02/10 5–12 min

Las 5 figuras que vamos a utilizar

Para empezar solo necesitamos cinco símbolos. Cada forma tiene un significado concreto.

INICIO / FIN
Terminador

Marca el comienzo o el final.

LEER / MOSTRAR
Entrada / salida

Recibe datos o muestra información.

PROCESO
Proceso

Calcula, cambia o guarda un dato.

¿CONDICIÓN?
Decisión

Pregunta algo y abre caminos Sí / No.

→
Flecha

Indica hacia dónde continúa el algoritmo.

1Empieza siempre en INICIO. 2Sigue las flechas. 3Un rombo debe tener, normalmente, una salida Sí y otra No. 4Todos los caminos deben continuar o terminar en FIN.
Libreta: dibuja los cuatro símbolos principales y escribe para qué sirve cada uno.

PASO 03/10 12–18 min

Estructura 1 · Secuencia

Una secuencia ejecuta los pasos uno detrás de otro, de arriba hacia abajo.

Entrada → proceso → salida. No hay decisiones ni repeticiones.

Problema

Calcular el perímetro de un rectángulo.

Algoritmo

  1. Leer la base.
  2. Leer la altura.
  3. Calcular P = 2 · (base + altura).
  4. Mostrar el perímetro.
Fíjate: Leer y Mostrar son entrada/salida, por eso usamos el paralelogramo. El cálculo es un proceso, por eso usamos el rectángulo.

PASO 04/10 18–25 min

Estructura 2 · Decisión

Una decisión aparece cuando el algoritmo tiene que elegir entre dos caminos.

El rombo formula una pregunta. Solo se recorre uno de los dos caminos.

Problema

Pedir un número e indicar si es par o impar.

Algoritmo

  1. Leer un número.
  2. Comprobar si el resto al dividir entre 2 es 0.
  3. Si es 0, mostrar “PAR”.
  4. Si no, mostrar “IMPAR”.
Pregunta importante: ¿por qué “Mostrar PAR” no debe ir dentro de un rectángulo?

PASO 05/10 25–32 min

Estructura 3 · Repetición

En un diagrama estándar, un bucle no necesita una “figura especial”. Se representa con una decisión y una flecha que vuelve atrás.

Si la condición es SÍ, se repite. Cuando es NO, se sale del bucle.

Problema

Mostrar los números del 1 al 5.

Algoritmo

  1. Guardar 1 en contador.
  2. Comprobar si contador ≤ 5.
  3. Si es SÍ, mostrar contador.
  4. Aumentar contador en 1.
  5. Volver a comprobar.
  6. Si es NO, terminar.
Idea clave: la flecha que vuelve a la condición es lo que crea la repetición.

PASO 06/10 32–38 min

¿Qué estructura necesito?

Secuencia

Cuando solo hay pasos en orden.

Paso 1 → Paso 2

Ejemplo: calcular un perímetro.

Decisión

Cuando hay que elegir un camino.

¿Se cumple?

Ejemplo: par o impar.

Repetición

Cuando una acción se repite.

Acción ↻

Ejemplo: contar hasta 10.

Clasifica: “Mayor de dos números”, “calcular el área”, “tabla de multiplicar”. ¿Cuál necesita secuencia, decisión o repetición?

PASO 07/10 38–44 min

Del diagrama a Scratch

Scratch no sustituye al algoritmo: lo implementa.

Ejemplo · Par o impar

al hacer clic en la bandera verde
preguntar “Escribe un número” y esperar
fijar número a respuesta
si <(número mod 2) = 0> entonces
decir “Es par”
si no
decir “Es impar”
ENTRADA “preguntar ... y esperar” PROCESO variables, operaciones y cálculos DECISIÓN bloque si / si no SALIDA “decir ...” o mostrar un resultado
Regla: primero dibuja la solución. Después busca qué bloques de Scratch hacen cada paso.

PASO 08/10 44–49 min

Errores frecuentes al hacer diagramas

1 · Forma incorrecta

Usar un rectángulo para “Leer número”.

Mejor: paralelogramo.

2 · Rombo sin Sí / No

Una decisión debe indicar claramente qué camino corresponde a cada respuesta.

3 · Flecha sin destino

Ningún camino debe quedarse “en el aire”. Debe continuar o llegar a FIN.

4 · Demasiado texto

Dentro de una figura escribe una instrucción breve:

“Calcular área”, no un párrafo completo.

5 · Empezar por el código

Si todavía no sabes explicar el algoritmo con tus palabras, es pronto para programarlo.

Comprobación rápida: revisa tu diagrama y señala con un círculo INICIO, una entrada, un proceso, una decisión si existe y FIN.

PASO 09/10 49–54 min

Reto guiado · Mayor de dos números

Enunciado

Pedir dos números y mostrar cuál es mayor. Si son iguales, indicarlo.

Antes de dibujar

  1. ¿Qué datos entran?
  2. ¿Qué queremos mostrar?
  3. ¿Necesitamos una decisión?
  4. ¿Qué preguntas debe hacer el rombo?

Pasos sugeridos

  1. INICIO.
  2. Leer A y B.
  3. ¿A > B?
  4. Si SÍ, mostrar A.
  5. Si NO, comprobar ¿B > A?
  6. Si tampoco, mostrar “Iguales”.
  7. FIN.
Trabajo en pareja: dibujad el diagrama en la libreta. Después construidlo en Scratch.
Ayuda: ¿qué bloques Scratch podrían aparecer?
  • preguntar ... y esperar
  • variables A y B
  • si / si no
  • operadores >
  • decir ...
